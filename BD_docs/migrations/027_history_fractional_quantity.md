# Миграция 027: дробное количество порций в истории заказов

## Дата выполнения
2026-08-14

## Файл
`server/migrations/027_history_fractional_quantity.sql`

## Что делает
```sql
ALTER TABLE slicer_order_history
  ALTER COLUMN total_quantity TYPE NUMERIC(21,3);
```
Обёрнуто в `DO $$ … $$` с проверкой текущего типа — миграция идемпотентна,
повторный запуск ничего не меняет.

**Чужие таблицы не затрагиваются.** `slicer_order_history` — наша таблица.

## Зачем
Количество в позиции чека заказчика — `docm2tabl1_items.docm2tabl1_quantity`
типа `NUMERIC(21,3)`. Три знака после запятой означают, что весовые позиции
(0.35 порции / кг) предусмотрены на уровне схемы. А наша
`slicer_order_history.total_quantity` была объявлена как `INT NOT NULL`
(миграция 001, строка 102).

Клиент считает `totalQuantity` как сумму `quantity_stack`, то есть напрямую
из этого `NUMERIC`. При дробном значении происходило следующее:

1. node-postgres отправлял `'0.35'`;
2. `int4in` отвечал ошибкой `22P02` (invalid input syntax for type integer);
3. транзакция `POST /api/orders/:id/complete` откатывалась;
4. клиент получал 500, в `catch` перезагружал доску — и карточка возвращалась.

Нарезчик не мог отдать такую позицию **вообще ничем**, кроме «Отмены»
(то есть с потерей записи в отчётах). Найдено полным ревью 2026-08-14
(находка №57).

## Что нужно проверить на живой базе
На момент миграции PostgreSQL был остановлен, поэтому фактическое наличие
дробных количеств не подтверждено. Проверочный запрос:
```sql
SELECT count(*) FROM docm2tabl1_items
 WHERE docm2tabl1_quantity <> trunc(docm2tabl1_quantity);
```
Если результат `0` — миграция всё равно полезна как страховка: одна кривая
строка чека больше не сможет намертво заблокировать карточку.

## Влияние на код
`server/src/routes/history.ts` — маппер приводит значение через `Number()`:
node-postgres отдаёт `NUMERIC` **строкой**, и без приведения на клиенте
вместо сложения получилась бы конкатенация (`"3" + "2" = "32"`).

## Откат
```sql
-- Только если в колонке нет дробных значений!
ALTER TABLE slicer_order_history
  ALTER COLUMN total_quantity TYPE INT USING round(total_quantity);
```
